# 判断の記録

ClaudeGaugeで、あとから見て理由が分からず、知らずに覆すと害のある判断を記録します。
次の2つを、両方満たすものだけを書きます。

- コードやコミットから、理由が読み取れない。
- 理由を知らずに覆すと、害がある(たとえば、トークンの漏えいや、配布の失敗)。

それ以外の理由は、コードのコメントか、PRの説明に書きます。挙動の決まりとその理由は、`docs/spec.md`にあります。ここに置くのは、ほかに書いていないものだけです。
理由が分からないものは、「理由の記録なし」と書いています。推測で補わないでください。

## 画面

### メニューバーの項目は、NSStatusItemとNSMenuで作る

詳細パネルは、`NSStatusItem`に付けた`NSMenu`の項目として、SwiftUIのビューを載せています(`StatusItemController`)。
`MenuBarExtra`や`NSPopover`に戻すと、「メニューバーを自動的に隠す」を有効にしているとき、パネルのボタンへポインターを下ろしただけで、アイコンが消えます。理由と、メニューの中で守ることは、`docs/spec.md`の7.2にあります。

## 認証情報とセキュリティ

### Keychainは`/usr/bin/security`経由で読む

- 決めたこと: `Security`フレームワークを直接使わず、`/usr/bin/security find-generic-password`を実行して読みます。
- 分かっていること: READMEに書いたとおり、通常は確認のダイアログが出ません。ログインキーチェーンがロックされているときなどは、macOSが確認を求めます。
- 理由の記録なし: 直接読む方式と比べた経緯は、記録が残っていません。変えるときは、確認のダイアログの出方が変わらないかを、先に調べてください。

### 配布するアプリは、ad-hoc署名で、公証なし

Apple Developerの正式な署名と公証は、行っていません。そのため、ブラウザからダウンロードしたアプリは、初回の起動を止められる可能性があります。READMEとリリースノートに、「システム設定」の「プライバシーとセキュリティ」から「このまま開く」を選ぶ手順を書いています。

## 更新の仕組み

### スリープ中の動きは、今のままにする

スリープ中も、時計は進む方式です(`ContinuousClock`)。復帰したとき、取得の時刻を過ぎていれば、すぐ取得します。ネットワークの失敗は、次の間隔まで待って、再試行します。期限切れのトークンは、案内の文言で知らせます。ユーザーに説明したうえで、この動きのままにしています。

## リリースの仕組み

### ドラフトを作ってから、人が公開する

- 決めたこと: リリースは、Actionsの`Draft release`でドラフトを作り、人が内容を確かめて、Publishします。Publishすると、`release.yml`がビルドして、zipを添付します。
- 理由: AIが書いたノートを、公開の前に人が見るためです。もう1つ、タグのルールセットがあります。`GITHUB_TOKEN`には、保護された名前のタグを作る権限がありません。ドラフトはタグを作らず、Publishしたときに、人がタグを作ります。ドラフトのリリースは、`release`イベントを発生させないので、`release.yml`は、Publishしたときだけ動きます。

### リリースノートのAIには、ツールを渡さない

- 決めたこと: Claude(Haiku)に、ツールを一切渡しません。変更の材料(コミット一覧と差分)は、トークンを持たないステップで集め、プロンプトに埋め込みます。
- 理由: 最初の設計は、`git diff`を許していました。しかし、`git diff --no-index /dev/null /proc/self/environ`で、任意のファイルを読めます。コミットのメッセージや差分に悪意のある指示が混ざると、Claudeのトークンを読んで、ハイライトに書き出せます。セキュリティレビューで見つかり、ツールをなくす設計に変えました。
- 補足: `claude-code-action`の`claude_args`は、`--tools ""`の空文字を、値のない旗に変えてしまいます(`parse-sdk-options.ts`)。そのため、害のない`TodoWrite`だけを渡しています。許可モードは`dontAsk`にします。リポジトリ側の設定を読ませないため、`--setting-sources user`と`--strict-mcp-config`を付け、作業フォルダも空にします。

### 公式のアクションと、購読のトークンを使う

- `anthropics/claude-code-action`に、`claude setup-token`で作ったトークンを渡します。
- Messages APIを、このトークンで直接呼ぶ方法は、使いません。利用規約に触れるおそれがあるためです。

### GitHub Actionsは、コミットのSHAで固定する

すべてのアクションを、コミットのSHAで固定しています。更新は、Dependabotが週に1回、提案します(公開から7日の待ちあり)。固定したSHAは、公式のタグと一致することを、`gh api repos/<owner>/<repo>/git/ref/tags/<tag>`で確かめます。注釈付きタグは、指す先のコミットまでたどります。

### 「Immutable releases」は、オフのままにする

`release.yml`が、公開のあとに、zipとチェックサムを添付するためです。オンにすると、公開後のファイルの追加ができなくなるおそれがあります。

## 公開に関すること

- 非公式のアプリで、自己責任であることを、READMEの冒頭に警告として置いています。文面はユーザーの指定です。
- 公開リポジトリのコミットの作者名とメールアドレスは、公開してよいと、ユーザーが明言しています。
